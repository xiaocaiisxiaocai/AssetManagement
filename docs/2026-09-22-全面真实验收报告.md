## 发现、修复与复验

| 问题 | 修复 | 实际验证 |
|---|---|---|
| 料件直接转移和受让人停用并发时，两个请求可能都成功，留下停用保管人 | 转移事务统一先锁用户、再锁料件；重新读取用户前清除旧跟踪状态 | 原测试真实失败；修复后并发用例内连续竞争 10 轮，受影响 48 项和完整 536 项通过；浏览器直接转移和审批转移均通过 |
| 项目工作台新增、删除料件后，主项目列表料件数不刷新 | 料件变化后同时刷新料件、流程与项目列表 | 浏览器新增后主表由 1 变 2，软删除后由 2 变 1，与 API 一致 |
| 借用、转让申请事由实际必填，但前端无必填标记，允许空白请求发往后端 | 必填标记与提交前校验共用规则；延期、归还仍可选 | 真实浏览器空事由显示提示，POST 请求数为 0；填写后成功提交 |
| 直接收回确认框声称“清空当前保管人”，与实际恢复原保管人的规则不符 | 提示明确优先恢复借出前保管人；原保管人不可用时由确认的所属组织负责人接收 | 真实确认框文本与收回后 API 保管人一致 |
| 已授权角色删除被后端正确拒绝，但产生未捕获 Promise / pageerror | 角色删除、保存、授权事件接入已有异常处理入口 | 真实重现 409 拒绝；修复后取消确认和 409 路径均不产生 pageerror，角色数据保留 |
| 新增料件默认带入项目负责人，却未同步归属部门，最小填写路径保存失败 | 同步负责人部门，处理异步选项加载、首 50 条之外的负责人；编辑不可修改字段不执行新增校验 | 真实浏览器只填写料件名称即可保存；另构造 50 个前置用户，末页负责人新增和刷新后的料件编辑均通过 |
| 404 页面“返回首页”落到根路由空壳，页面空白 | 404 显式回首页，已鉴权根路由重定向到用户首页或默认首页 | 最终脚本对三个角色分别验证 404→首页、直接访问根路径→首页，全部通过 |

另修复资产导入测试使用固定姓名、被同类测试累积成重名的问题，改用唯一工号输入；保留同名需要工号的业务约束。
