# 并发与导入旧响应修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不新增数据库迁移的前提下，关闭部门负责人并发重复分配窗口，并阻止导入校验旧响应在清空文件或关闭弹窗后回填。

**Architecture:** 后端通过统一事务锁顺序，使候选负责人行锁成为事务中的首次数据库读取，随后再读取部门并检查占用；前端抽取通用导入校验会话，集中管理文件、预览、loading 和请求代次，两个导入入口只通过该会话更新状态。

**Tech Stack:** ASP.NET Core 8、EF Core 8、MySQL 5.7、xUnit、Vue 3、TypeScript、Vitest。

## Global Constraints

- 不新增数据库迁移或唯一索引。
- 不修改部门、用户、测试项目导入接口的数据结构。
- MySQL 5.7 默认隔离级别为 `REPEATABLE-READ`，测试必须覆盖等待行锁后的可见性。
- 后端业务异常继续使用 `4094 / 负责人已负责其他部门`。
- 前端界面文案保持中文，复用现有 `createLatestRequestGuard`。
- 后端构建与测试顺序执行，避免共享输出目录锁冲突。

[Fact]
public async Task Concurrent_department_updates_cannot_assign_the_same_manager()
{
    await Login();
    var manager = await CreateUser();
    var first = await Post<ApiResult<DepartmentNodeDto>>(
        "/api/departments",
        new CreateDepartmentRequest { Name = Unique("并发部门甲") });
    var second = await Post<ApiResult<DepartmentNodeDto>>(
        "/api/departments",
        new CreateDepartmentRequest { Name = Unique("并发部门乙") });

    await using var scope = _factory.Services.CreateAsyncScope();
    var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
    await using var blocker = await db.Database.BeginTransactionAsync();
    await db.Users
        .FromSqlInterpolated($"SELECT * FROM users WHERE Id = {manager.Id} FOR UPDATE")
        .AsNoTracking()
        .ToListAsync();

    var firstRequest = _client.PutAsJsonAsync(
        $"/api/departments/{first.Data!.Id}",
        new UpdateDepartmentRequest
        {
            IsActive = true,
            ManagerId = manager.Id,
            Name = first.Data.Name
        });
    var secondRequest = _client.PutAsJsonAsync(
        $"/api/departments/{second.Data!.Id}",
        new UpdateDepartmentRequest
        {
            IsActive = true,
            ManagerId = manager.Id,
            Name = second.Data.Name
        });

    await WaitForBlockedDepartmentUpdatesAsync(db, expectedWaiters: 2);
    await blocker.CommitAsync();
    var responses = await Task.WhenAll(firstRequest, secondRequest);

    responses.Count(x => x.IsSuccessStatusCode).Should().Be(1);
    responses.Count(x => x.StatusCode == HttpStatusCode.Conflict).Should().Be(1);

    await using var verifyScope = _factory.Services.CreateAsyncScope();
    var verifyDb = verifyScope.ServiceProvider.GetRequiredService<AppDbContext>();
    var assignedCount = await verifyDb.Departments.AsNoTracking()
        .CountAsync(x => x.IsActive && x.ManagerId == manager.Id);
    assignedCount.Should().Be(1);
}

private static async Task WaitForBlockedDepartmentUpdatesAsync(
    AppDbContext db,
    int expectedWaiters)
{
    var deadline = DateTime.UtcNow.AddSeconds(10);
    var actualWaiters = 0;
    while (DateTime.UtcNow < deadline)
    {
        actualWaiters = await db.Database.SqlQueryRaw<int>(
                """
                SELECT COUNT(*) AS Value
                FROM information_schema.innodb_lock_waits waits
                JOIN information_schema.innodb_trx blocker
                  ON blocker.trx_id = waits.blocking_trx_id
                WHERE blocker.trx_mysql_thread_id = CONNECTION_ID()
                """)
            .SingleAsync();
        if (actualWaiters >= expectedWaiters) return;
        await Task.Delay(25);
    }

    throw new TimeoutException(
        $"等待部门更新进入行锁队列超时，预期 {expectedWaiters}，实际 {actualWaiters}");
}
```

辅助等待函数轮询 `information_schema.innodb_lock_waits`，并用 `CONNECTION_ID()` 只统计被当前阻塞事务挡住的请求；最多等待 10 秒，达到两个等待事务后返回，超时则抛出带实际等待数的 `TimeoutException`。

import { describe, expect, it } from 'vitest';

import { createImportValidationSession } from './import-validation-session';

describe('导入校验会话', () => {
  it('清空文件后拒绝旧请求写回', () => {
    const session = createImportValidationSession<{ name: string }>();
    const generation = session.start(new File(['a'], 'a.xlsx'))!;

    session.reset();

    expect(session.canApply(generation)).toBe(false);
    expect(session.selectedFile.value).toBeNull();
    expect(session.rows.value).toEqual([]);
    expect(session.loading.value).toBe(false);
  });

  it('选择新文件后只接受最新请求', () => {
    const session = createImportValidationSession<{ name: string }>();
    const first = session.start(new File(['a'], 'a.xlsx'))!;
    const second = session.start(new File(['b'], 'b.xlsx'))!;

    expect(session.canApply(first)).toBe(false);
    expect(session.canApply(second)).toBe(true);
  });

  it('空文件选择会使在途请求失效', () => {
    const session = createImportValidationSession<{ name: string }>();
    const generation = session.start(new File(['a'], 'a.xlsx'))!;

    expect(session.start(null)).toBeNull();
    expect(session.canApply(generation)).toBe(false);
  });
});
```

- [ ] **Step 3: 编写最小会话实现**

新增 `import-validation-session.ts`：

```typescript
import { ref, shallowRef } from 'vue';

import { createLatestRequestGuard } from './latest-request';

export function createImportValidationSession<Row>() {
  const guard = createLatestRequestGuard();
  const loading = ref(false);
  const rows = shallowRef<Row[]>([]);
  const selectedFile = shallowRef<File | null>(null);

  function reset() {
    guard.invalidate();
    selectedFile.value = null;
    rows.value = [];
    loading.value = false;
  }

  function start(file: File | null) {
    reset();
    if (!file) return null;
    selectedFile.value = file;
    loading.value = true;
    return guard.next();
  }

  function canApply(generation: number) {
    return guard.isLatest(generation);
  }

  function finish(generation: number) {
    if (canApply(generation)) loading.value = false;
  }

  return { canApply, finish, loading, reset, rows, selectedFile, start };
}
```
