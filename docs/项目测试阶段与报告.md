# 项目测试阶段与报告

项目跟进工作台按“料件 → 项目进度 → 测试阶段与报告”排列。料件清单自动适应记录数，超过可视高度时只在表内滚动。原有料件流转审批、落地跟进记录继续保留。

## 测试阶段台账

每个项目可以建立多个阶段，按序号排列。阶段记录名称、目标、测试内容、测试结果、起止日期和状态。序号在同一项目中唯一，范围为 1–999。

阶段状态包括未开始、进行中、受阻、已完成。每个项目最多存在一个进行中或受阻阶段，该阶段即当前阶段。切换到下一阶段前，应先完成或调整当前阶段。

进行中或受阻阶段需要开始日期；已完成阶段需要起止日期、测试内容和测试结果，结束日期不能早于开始日期或晚于业务当天。项目整体进度与测试阶段分别维护，阶段完成不自动结案项目。

项目处于规划中或测试中时，项目负责人、拥有项目管理权限的人员和管理员可新增、编辑、删除阶段及上传、移除报告；进入落地跟进或已结案后测试台账锁定，仅保留查看、下载和导出历史资料。其他拥有项目查看权限的用户可以查看台账和下载报告。项目删除后工作台保持只读。并发编辑通过版本校验防止覆盖；失败时前端保留输入。含报告的阶段需先处理关联报告后才能删除。

## 报告归档

报告入口直接放在阶段台账每行的“报告附件”列，点击“上传报告”选择文件后自动关联该阶段，无需再选择阶段；文件名可直接点击下载，“附件”弹层提供该阶段的完整附件列表和删除入口。系统不单独上传项目总报告，结案阶段的报告作为项目总报告。工作台不再另设独立报告区域。

单个报告最多 20MB，支持 PDF、DOCX、XLSX、PPTX、PNG、JPG/JPEG；后端同时检查文件扩展名和实际格式，不接受含宏的 Office 文件。

每份文件保存文件名、阶段归属、说明、上传人、上传时间和大小。下载经过项目接口鉴权，存储文件名不对外公开。移除报告为逻辑删除，保留原文件以便归档。项目有阶段或报告历史时禁止彻底删除。

报告存储在 `Attachment:Path` 下的 `project-reports` 子目录，包含在现有附件备份中，不受孤儿图片清理影响。

## 导出

- 阶段 Word 报告：包含项目资料、料件、所选阶段的测试内容、测试结果和该阶段附件目录。
- 项目完整 Word 报告：包含项目资料、全部料件、全部阶段和测试结果、附件目录、落地跟进及料件流转摘要。
- 完整资料包 ZIP：包含同范围的 Word 报告、可离线打开和打印的 HTML 报告、对应原始报告附件。HTML 中的附件链接指向包内文件，适用于向厂商或管理层交付。

项目负责人可以导出本人项目；具有 `project:export` 权限的用户可以导出其可查看的项目。单个资料包附件合计上限 200MB，超出时按阶段导出。Word 报告保留原始测试文字；PDF/Office 原件随 ZIP 提供，不转换或改写原报告内容。

## 升级

数据库迁移 `AddProjectTestingStagesAndReports` 新建 `project_test_stages` 与 `project_report_documents` 两张表，不改写原有项目、料件或跟进记录。新增阶段初始为空，由项目负责人按真实测试过程录入。部署时先应用迁移，再启动新版本 API。

接口入口为 `/api/test-projects/{projectId}/workspace`，其下提供阶段、报告附件、Word 报告和资料包操作。
